# Лабораторная работа №1: сбор постов VK

Скрипт собирает посты сообщества Самарского университета за период
с 1 по 31 августа 2026 года включительно и сохраняет их в CSV.

## Установка

Нужен Python 3.10 или новее. Команды для PowerShell из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Версии зависимостей зафиксированы по установленному окружению проекта.

Создайте в папке проекта файл `.env` и укажите свой токен VK API
с доступом к чтению стены сообщества:

```dotenv
VK_TOKEN=ваш_токен
```

## Запуск

```powershell
.\.venv\Scripts\python.exe parser.py
```

По умолчанию результат сохраняется в `output/posts.csv`.
Каталог создаётся автоматически, существующий файл результата перезаписывается.
Для другого сообщества, периода или пути:

```powershell
.\.venv\Scripts\python.exe parser.py --group_domain samara_university --start_date 2026-08-01 --end_date 2026-08-31 --output output/august/posts.csv
```

Справка по параметрам:

```powershell
.\.venv\Scripts\python.exe parser.py --help
```

Даты задаются в формате `YYYY-MM-DD`; обе границы включены.

## Результат

CSV использует разделитель `;` и кодировку UTF-8 с BOM для открытия в Excel.
Столбцы определяются по ключам всех собранных записей. Сейчас сохраняются:

- `id`, `owner_id` — идентификаторы поста и владельца стены;
- `date`, `text` — дата публикации и текст;
- `likes`, `comments`, `reposts`, `views` — счётчики активности;
- `is_repost` — `True` для репостов с непустым `copy_history`, иначе `False`;
- `url` — ссылка на пост.

Для репостов поле `text` содержит собственный комментарий и доступные тексты
исходных записей из `copy_history`. Переносы строк заменяются пробелами.
Дата, ссылка и счётчики относятся к записи на стене собираемого сообщества.

Посты сохраняются от старых к новым, повторы исключаются.
При пустой выборке файл не создаётся, существующий файл не изменяется.

При ошибке VK API выводится предупреждение о неполной выгрузке.
Уже собранные записи сохраняются отдельно: например, вместо `posts.csv`
создаётся `posts.partial.csv`. Основной файл остаётся без изменений.
Предыдущий файл с таким же именем `.partial.csv` перезаписывается.
Если записей нет, файл не создаётся. Код завершения при ошибке API — `1`,
при завершении сбора без ошибки — `0`. В PowerShell его можно посмотреть
через `$LASTEXITCODE` сразу после запуска. Файл `.partial.csv` не следует
считать полным результатом лабораторной; после устранения ошибки повторите запуск.

## Лабораторная работа №2

Откройте `lab2.ipynb` и выполняйте ячейки сверху вниз. Для запуска JupyterLab
из папки проекта:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m jupyterlab lab2.ipynb
```

В VS Code можно открыть notebook напрямую и выбрать ядро `.venv` проекта.
Первая ячейка параметров задаёт `INPUT`, `OUTPUT`, фильтрацию и параметры TF-IDF
и кластеризации. Словарь `ALGORITHMS` содержит подписи и созданные в notebook объекты моделей:

```python
ALGORITHMS = {
    "KMeans": KMeans(random_state=42, n_init=20),
    "MiniBatchKMeans": MiniBatchKMeans(random_state=42, n_init=20, batch_size=256),
    "Agglomerative": AgglomerativeClustering(metric="cosine", linkage="average"),
    "DBSCAN": DBSCAN(eps=0.8, min_samples=3, metric="cosine"),
}
```

`cluster_documents(matrix, algorithms=ALGORITHMS, max_clusters=MAX_CLUSTERS)`
копирует модели через `sklearn.clone` и меняет только `n_clusters` при переборе k.
Остальные настройки сохраняются, исходные объекты остаются неизменными.
Подписи произвольные; функция не выбирает реализацию по имени. Можно передать
другие sklearn-модели с `fit_predict`. Модели без `n_clusters`, включая DBSCAN,
запускаются один раз с настройками из notebook. Для DBSCAN экспериментально
меняйте `eps` и `min_samples`. Шум обозначается `-1` в таблицах и серыми крестиками
на графике. В `comparison.csv` он учитывается отдельно в `noise_count`.
Силуэт вычисляется без шума; при менее двух кластерах остаётся пустым.
Сравнивайте его вместе с числом исключённых точек: оценка относится к части корпуса.
Для итоговой сдачи используйте минимум три алгоритма. График подстраивается под их число.
После изменения параметров используйте **Restart Kernel and Run All Cells**.
Таблицы и график отображаются прямо в notebook. Для просмотра постов конкретного
кластера измените `ALGORITHM_TO_VIEW` и `CLUSTER_TO_VIEW` в соответствующей ячейке.
Последняя ячейка сохраняет итоговые результаты.

Функции распределены по трём модулям:

- `lab2/preprocessing.py` — загрузка, очистка и токенизация;
- `lab2/word_count.py` — лемматизация, частотный словарь и его сохранение;
- `lab2/clustering.py` — TF-IDF, кластеризация, таблицы, график и сохранение результатов задания 3.

Исходные данные — `inputs/posts.csv` первой лабораторной (UTF-8, разделитель `;`,
столбец `text`). Подключение к VK не требуется. Пути задаются относительно папки
проекта, например `INPUT = Path("output/posts.csv")`.

Обработка выполняется в памяти: очистка ссылок и спецсимволов, нижний регистр,
удаление пустых текстов и дубликатов, лемматизация PyMorphy3, фильтрация частей речи,
TF-IDF. Промежуточные CSV, матрицы NPZ и настройки JSON не сохраняются.
Упоминания VK сохраняют подпись; русские и английские буквы сохраняются, цифры
и пунктуация разделяют слова. PyMorphy3 выбирает первый разбор без учёта контекста.
Фильтруются PREP, CONJ, PRCL, NPRO, INTJ; это базовая фильтрация, не полный список
стоп-слов. Параметр `KEEP_STOP_WORDS = True` отключает её.

TF-IDF использует L2-нормализацию, сглаженный IDF, обычные частоты TF.
Параметры: `MIN_DF = 2` (число документов), `MAX_DF = 0.9` (доля документов),
`MAX_FEATURES = 5000`, `NGRAM_RANGE = (1, 2)` (леммы и пары после фильтрации).

Сравниваются KMeans, MiniBatchKMeans и агломеративная кластеризация с average linkage
и косинусным расстоянием. Первые два метода используют евклидово расстояние
на нормированных TF-IDF-векторах. Для методов с `n_clusters` перебирается k от 2 до
`MAX_CLUSTERS = 8`, но не более числа документов минус один. Выбирается наибольший
косинусный силуэт в исходном пространстве признаков; при равенстве — меньшее k.
Случайное зерно 42, n_init=20. Результаты экспериментов сохраняются для сравнения.
Силуэт ближе к 1 означает более отчётливое разделение; малая величина не доказывает
наличие тематически чётких групп. Оценка на этом же корпусе является разведочным
сравнением, а не проверкой качества на независимых данных.

Итоговые файлы в `output/lab2`:

- `word_counts.csv` — частотный словарь, столбцы word и count;
- `clusters.csv` — алгоритм, индекс документа, кластер и очищенный текст поста;
- `cluster_sizes.csv` — размеры кластеров и семь терминов с наибольшим средним TF-IDF;
- `comparison.csv` — силуэты всех проверенных k и отметка выбранного результата;
- `clusters.png` — графики выбранных алгоритмов в общей проекции PCA с подписями осей и легендами.

CSV записываются в UTF-8 с BOM, разделитель `;`. Индексы документов начинаются
с нуля и относятся к корпусу после очистки и удаления дубликатов, а не к ID VK.
Номера кластеров у разных алгоритмов не обозначают одинаковые темы.
PCA используется только для рисунка; двумерная проекция теряет информацию,
доля сохранённой дисперсии указана в заголовке. Термины помогают интерпретировать
кластеры, но не являются автоматически установленными названиями тем.

Функции предполагают корректные параметры notebook, модели с `fit_predict` , минимум три документа с ненулевыми признаками и минимум два
признака для PCA. Ошибки параметров передаются напрямую из библиотек. При нулевых строках расчёт
выдаёт ошибку до записи результатов: попробуйте `MIN_DF = 1`, `MAX_DF = 1.0`.
Для агломеративной кластеризации и PCA матрица преобразуется в плотный массив;
реализация рассчитана на небольшой корпус лабораторной. Файлы результатов
перезаписываются при успешном повторном расчёте.
